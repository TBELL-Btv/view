2. 왜 일반적인 방법으로는 안 되는가 — 3가지 전제

V1과 같다. 구현이 이 전제를 확인한 상태다.

전제 1 — UI 객체를 인식할 수 없다

메뉴·버튼이 네이티브 UI 요소로 존재하지 않는다. 셀렉터 기반 자동화는 쓰지 않는다. 화면은 이미지(OCR·영역 휘도)와 시스템 상태(dumpsys)로 판독한다.

전제 2 — 화면 확보 경로는 2가지다

대상확보 방법V2
정지 화면ADB screencap구현됨 실기·mock
움직이는 화면HDMI 캡처보드 → PC이후 단계. 재생 여부는 오디오 세션으로 대체

실측: 방송·재생 영역은 ADB 캡처 시 검정으로 찍힌다. VOD 본편 픽셀 판정은 ADB만으로는 불가하다.

전제 3 — 실시간 판독 모델은 아직 붙이지 않았다

판독은 RapidOCR(로컬)과 결정론 지표다. Judge 프로토콜(Judge.extract)은 두었고, 현재 구현은 OcrRuleJudge다.

4. 핵심 판정 정책 — 기능과 디자인의 분리

V1 정책을 코드·문서 스키마에 반영했다.

판정조건처리V2
PASS 기능 정상 + UI가 기준과 일치 통과 스위트 기본 결과
PASS (변경 감지) 기능 정상 + 디자인만 변경 통과 집계 + 하이라이트 + 알림 PASS_CHANGED. notify jsonl / webhook. 대시보드 파란 배지
FAIL 기능 불일치 제품 결함 JIRA 훅(URL 없으면 dry-run 로그)
ERROR 전제 미충족·장비/판독 불가 FAIL과 분리 집계 좌측 Wing 미확보·신호 팝업·오디오 전제 실패 등

spec.md에서 ## 기능 규칙 불일치 → FAIL, ## 디자인 치수·색·폰트 불일치 → PASS(변경 감지), ## 전제 미충족 → ERROR.

구현 관점: AI에게 합격을 묻지 않는다. OCR이 텍스트·박스를 주고, 화면별 page 코드가 스키마를 적용한다.

V1 Phase 1~3을 랩 구현 플랜 P0~P4에 대응했다. 캡처보드 트랙은 이 표와 병행하지 않는다.

V1현재 Phase내용상태

Phase 1 기준 P1 버전드 baseline, 변경 알림, OCR 덤프 핵심 반영
